## Architecture

Single-package Flutter app. All source lives flat in `lib/` with no sub-directory layering.

- `main.dart` — entry point; initializes theme via `Provider`, routes to `HomePage` or `Tutorial`
- `home_page.dart` — main menu (difficulty selection, new/continue game, leaderboard)
- `game.dart` — game screen (timer, number pad, action buttons)
- `game_board.dart` — 9x9 board widget + core game logic (generation, fill, markup, validate, undo, win detection). Largest and most complex file (~660 lines).
- `sudoku.dart` — data models (`Sudoku`, `Cell`, `Position`) with JSON serialization
- `save_manager.dart` — singleton backed by `SharedPreferences`; handles game saves, scores, theme prefs, tutorial state
- `theme.dart` — `ThemeProvider` (ChangeNotifier); generates Material You color schemes from a seed color
- `stack.dart` — generic LIFO stack used for undo
- `move.dart` — undo record (position, value, markup)
- `painters.dart` — `CustomPainter` subclasses for logo and grid lines
- `util.dart` — time formatting, difficulty-to-empty-squares mapping, URL launcher

### Key patterns

- State management: `setState` + `Provider` (no complex state library)
- Undo: each move pushes a `List<Move>` to a LIFO stack; placing a number also records auto-removed markups from the same row/column/box as additional moves in the same stack entry
- Difficulty: 5 levels mapped to empty-square counts via `difficultyToEmptySquares()` in `util.dart`
- Puzzle generation: delegated to `sudoku_solver_generator` package
- Persistence: all data in `SharedPreferences` (JSON-encoded game state, string-list scores, bool/int settings)

## Conventions

- Formatter: page width 200 (`analysis_options.yaml`)
- Lint rules: `package:flutter_lints/flutter.yaml` (default set, no custom rules)
- Some user-facing strings in `game.dart` are hardcoded in English and not localized (dialog prompts like "Are you sure...")
- `SaveManager` is a singleton accessed via `SaveManager()`; many async methods lack `await` at call sites
